This is a thought experiment. We want to write a program that checks its own correct working. The program will do nothing other than attempt to check if it is executing as programmed. So let’s build one.

An algorithm at the highest level is a process that takes an input, performs computation, and produces an output. There are various steps on the way.

In our algorithm, the first step will be to read an input. The important property of this input is that it is generated from outside the algorithm. An external source. It is important because we build algorithms to interface with the external world.

The concept of computation has 2 basic components to it. Process and memory. An action and a store of information. These two separate isolated components need to work together for computation to take place.

So our processor reads the value from outside and stores it in the memory. We assume that this is an isolated processing task. Meaning no new information other than the input was generated at this step. This is not strictly necessary as will be evident later, but we want to keep it simple.

The second step would be to compute a hash of the input. This hash will generate a unique signature of the input that we read. No input other than this particular input will have the same signature. This computation of course generates its own memory, meaning new information.

Third step will be to compute a hash of the original input plus all the new memory that was generated in the computation of second step. This will give us a second hash.

The significance of this second hash is: it is a unique signature of input as well as the processing part of our computation.

Now there are assumptions that go with this. The hashing computation that is performed for a particular input produces a deterministic memory footprint. Meaning computing the hash of the same input infinite times generates the same intermediate information every time. There is no degree of randomness involved in the hashing algorithm. Second assumption is that two distinct processes never produce the same memory footprint. With this we can construct a signature of the process.

Now our algorithm is semi complete. We have a signature of the process. We can store this hash and compare every new execution of this algorithm and check if it produces the same hash. If it doesn’t, then we can conclude that the algorithm did not execute correctly.

But wait. Comparing two hashes is also computation, having its own process and memory footprint. What guarantees the correct execution of this computation?

The answer to that question is the very algorithm we built. Let’s add one more step to do it.

This computes the hash of all the previous information plus new information that was generated by the comparison computation. Now we have a new final hash which we can compare with a known hash to see if execution was correct.

Which adds one more computation step to our algorithm. This produces an infinite loop.

To check the correctness of this algorithm we always end up with an extra step whose correctness we cannot check. Thus making our original algorithm impossible to construct.

If an algorithm that can check its own correct execution cannot exist, then so can’t any algorithm that does something extra and check its own correct execution.

Another more practical problem is: the primary assumption we made was a process having deterministic memory footprint, thus making it possible for us to construct a signature of the process itself. Which is an impossibility in many situations. Most primarily in algorithms which have a degree of randomness. Many cryptographic algorithms have this, maybe even hashing algorithms themselves. We also cannot guarantee that the second assumption will play out. Why can’t we have two distinct processes with same intermediate memory footprint? There is nothing that’s stopping this from happening.

Giving the deterministic scenario a chance, we can have something that’s good enough, but never perfect. We have this in many cases, for example information sent over network needs to be verified if it was sent correctly, we have a hash or something similar to a hash in this scenario. There is a tiny probability that we receive incorrect information that goes unnoticed. But the probability is so tiny, that it doesn’t matter in real world. For this scenario to play out, we need error in the information as well as error in the hash such that errored hash verifies the errored information. I am not aware if something like this has ever happened, but it will be fascinating to find out if it has, and what consequences it produced.

The second assumption we made is a bigger problem practically. With network information, we’re only checking the integrity of the information and not the process itself. So the central problem remains: we cannot sign a process, only information.

But even if we could sign a process through some means, the logical impossibility of checking correctness still remains as demonstrated in the algorithm. Which is why we made that assumption.

A computation cannot check its own correctness. Checking correctness needs to be an external process, which also cannot be guaranteed to be correct.
